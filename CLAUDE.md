# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A pilot logbook web app — flight logging, dashboard, route map, duty tracker, **currency/recency tracking** (TC built-ins + custom rules), pilot profiles (with de-duplication/merge), a per-user aircraft **fleet manager**, aviation-document tracking (with Transport Canada expiry math), CSV import/export, **PDF export** (summary + TC-style logbook pages), logbook scanning (on-device iOS OCR + opt-in **cloud AI** that also powers website scanning), a first-run onboarding wizard, and bug reporting.

It is a **Next.js 15 (App Router) + TypeScript** app that builds to a **static export** (`output: "export"` → `out/`). That same `out/` is served by Vercel as a static site and bundled into a native **iOS app via Capacitor** (`capacitor.config.ts`, `webDir: out`). Because it's a fully client-side static export, there are **no Next.js server/API routes**. The iOS app adds native capabilities on top of the web bundle — on-device OCR scanning, home/lock-screen widgets, and deep links (see **Native iOS** below).

The data layer is **Supabase Auth + Row Level Security**: the browser talks to Supabase directly with the **public anon key**, and RLS scopes every row to its owner. A localStorage mirror provides offline resilience and holds bug-report screenshots. When Supabase env vars are absent the app runs **local-only** (auth + data entirely in the browser).

## Commands

```
npm install
cp .env.example .env.local   # add NEXT_PUBLIC_SUPABASE_URL + NEXT_PUBLIC_SUPABASE_ANON_KEY (both public)
npm run dev          # http://localhost:8090
npm run build        # static export to out/ + full type check — run this to verify changes
npm run lint
npm run build:mobile # next build && cap sync (refresh the iOS bundle)
npx tsx evals/run.ts # feature evals — 21 suites over the pure lib code, seconds, no network
```

There is no unit-test framework. Verify with `npm run build` (type errors surface
here), the preview tools, and **`npx tsx evals/run.ts`** — the eval suites in
`evals/` assert behavior across every feature in `src/lib` and exit non-zero on a
failed check. Results, findings and known coverage gaps are recorded in
`EVALS.md`; run them before a release and add a suite alongside any new feature.

## Architecture

### Data flow
- **`src/context/DataContext.tsx` is the single client-side state owner.** In cloud mode it subscribes to Supabase Auth (`onAuthStateChange`), loads the signed-in user's `plb_app_state` row (RLS-scoped), runs `migrateData`, and holds the whole `AppData` in React state. Components never fetch directly — they read `data` and call `mutate((draft) => …)` / `replace(next)`.
- Persistence is **merge-on-write** (`pushState` in `DataContext`): every mutation writes the localStorage mirror immediately and debounces a cloud push. The push probes the row's `updated_at`; if another client wrote since our last sync, it three-way merges **base + local + server** per entity (`src/lib/merge.ts`) before writing, and the write itself is a conditional `UPDATE … eq(updated_at, seen)` so races retry instead of clobbering. The merge ancestor ("base" = last synced server state) is persisted per user via `loadBase`/`saveBase` in `clientStore.ts`. `mutate`/`replace` stamp changed entities (`stampChanges`) — flights use `updated_at`, everything else `updatedAt` — which is how same-entity conflicts resolve (newest wins). `loadCloudState` merges offline mirror edits instead of discarding them. Bug-report screenshots are stripped before any cloud write or merge (`stripScreenshots`) and re-merged from the local cache (`mergeScreenshots`).
- **`ready` gates the authed shell.** It must go back to `false` while a newly signed-in user's row loads; otherwise the layout renders the previous (empty) `data` and briefly flashes the onboarding wizard. `loadCloudState` restores it on every path.
- **Mirror-first boot / offline session (iOS).** `applySession` (in `DataContext`) drives Supabase `onAuthStateChange`. A remembered user is persisted via `loadLastUser`/`saveLastUser`/`clearLastUser` (`clientStore.ts`); at boot, if that user has a local mirror the app shows it immediately (`syncState: "offline"`) instead of blocking on the network, so a cold offline launch still opens the logbook — a pilot must never be locked out of a legal document. When the real session confirms, edits in the mirror merge-sync as usual. `SIGNED_OUT` (and an explicit `logout`) clears the remembered user.
- **Local-only fallback:** when `supabaseConfigured()` is false (no `NEXT_PUBLIC_SUPABASE_*` env), auth and data use localStorage via `src/lib/clientStore.ts`. Local passwords are salted **SHA-256** (legacy unsalted djb2 records are verified then upgraded in place). Keep both cloud and local paths working when touching auth or persistence.

### Auth & data (client-side, under RLS)
- **Supabase Auth (email/password)** — `login`/`signup`/`logout` in `DataContext` call `supabase.auth.*`. Signup with email-confirmation on returns `needsConfirmation` (the login page shows a "check your email" prompt). `src/lib/supabaseClient.ts` builds the browser client from the **public anon key** — safe to ship; RLS does the enforcing.
- **One table, `plb_app_state`** (`user_id uuid → auth.users`, `data jsonb`): the whole per-user logbook (flights, duty, pilots, profile, documents, and that user's private bug reports). Screenshots never leave the browser. Authoritative DDL is `supabase/schema.sql`; RLS policies require `auth.uid() = user_id` on select/insert/update/delete.
- **The exceptions to "anon key only" are the Edge Functions** (`supabase/functions/`): `delete-account` holds the service-role key *server-side* (App Store account-deletion requirement; caller identified from their own JWT, can only delete themselves), and `scan-extract` holds the **ANTHROPIC_API_KEY** for the opt-in cloud AI scanner (JWT-required, relays images to Claude vision, stores nothing; the client re-sanitizes its JSON via `sanitizeFmFlights`/`sanitizeFmDocument` in `scan.ts`). Neither key is ever in the app bundle. Deploy with `supabase functions deploy <name>`; `scan-extract` needs `supabase secrets set ANTHROPIC_API_KEY=…` (optional `SCAN_MODEL` override).
- **Billing (Stripe, web).** Premium is **server-authoritative**: the `plb_entitlements` table is **read-your-own only with no client write policy**, so only the `stripe-webhook` Edge Function (service-role) grants/revokes it — never put entitlement in `plb_app_state` (that row is user-writable). `stripe-webhook` verifies the Stripe signature and maps price→tier via `STRIPE_PRICE_MAP` (deploy `--no-verify-jwt`; secrets `STRIPE_SECRET_KEY`/`STRIPE_WEBHOOK_SECRET`/`STRIPE_PRICE_MAP`). The client interprets the row with **pure `entitlement.ts`** (`effectiveTier` with a `GRACE_DAYS` offline window, `hasFeature`, `entitlementFromRow`), read offline-first by `useEntitlement`; gate features with `<PremiumGate feature="…">` or `useEntitlement().has(...)`. **Enforcement is ON**: AI scan / doc OCR / pro PDF / custom currency rules are Pro; the Duty page is Professional (see `FEATURE_MIN_TIER`). Gated surfaces show a PRO/lock affordance that routes to `/pricing`; a gradient **Upgrade** link shows in the Sidebar for non-premium users. `/pricing` plan buttons start a Stripe Payment Link checkout via `lib/checkout.ts` (`client_reference_id` = user id, appended to the link URL — do **not** enable Stripe's "collect client reference id" field). Test-mode is verified end-to-end and live on the site; live-mode Stripe is pending incorporation. Full operator setup is in `BILLING.md`.

### Framework-free logic (`src/lib`) — keep it pure
- **`migrate.ts` is the compatibility spine.** `migrateData` runs on every load and upgrades legacy data: `year/month/day` → `date`, `civilIdent` → `registration`, promotes free-text PIC/SIC/SOC into real pilot profiles, back-fills `pilotId/picId/sicId/socId`, normalizes `flightColumns`, and synthesizes a `profile` for pre-onboarding users. Extend it when adding/renaming fields rather than assuming stored data has them.
- Flights carry both structured IDs and **backward-compatible text mirrors** (`pic/sic/soc`, `year/month/day`, `civilIdent`) used by CSV export — keep both in sync. `syncFlightMirrors` (in `logbook.ts`) re-derives them; call it inside a `mutate` draft after edits (see `FlightForm.tsx` / `FlightTable.tsx`).
- `csv.ts` — export + import. Import is the intricate part: `detectStructuredLogbook` branches between a flat CSV and a grouped/multi-header Transport-Canada-style logbook; `importCSV`/structured import are **pure** (take + return `AppData`) and the logger page clones data before calling them, then `replace()`s the result.
- `pilots.ts` — dedupe (`pilotDupKey`, `findDuplicateClusters`) and `applyMerge`/`applyDeletePilot` which re-point every flight reference before deleting a profile.
- `documents.ts` — aviation-document catalog (`DOC_TYPES`) plus **pure Transport Canada expiry math**: `computeAutoExpiry`/`medicalValidityMonths` (medical validity depends on age-at-exam), `documentStatus` (valid/expiring/expired).
- `flightColumns.ts` — canonical Logged-Flights column set + `normalizeFlightColumns` (the per-user visible/ordered subset lives in `AppData.flightColumns`).
- `id.ts` — `uid(prefix)` mints collision-safe ids (per-session counter + random suffix). Use it instead of `Date.now() + Math.random()`, which collides during bulk CSV imports.
- `scan.ts` — the OCR extraction schema + **pure** heuristic parser for the native scan pipeline. Turns raw OCR pages (and an optional Apple-Intelligence Foundation-Models extraction) into `ScannedFlight`/`ScannedDocument` candidates with **per-field confidence** (0..1), targeting the *real* `Flight`/`PilotDocument` field names. `parseFlightsFromOcr`/`parseDocumentFromOcr` are the heuristic path; `combineFlights`/`combineDocument` fold in the model extraction; fields below `LOW_CONFIDENCE` (0.7) are highlighted in the confirm sheet. **Scans are never auto-saved** — the pilot approves the pre-filled sheet.
- `currency.ts` — **recency math** (pure): TC built-ins (CAR 401.05 day/night passenger recency, IFR 6h+6 approaches, all over calendar-month windows) plus user-defined `AppData.currencyRules` (day windows, optional per-type scope). Flights carry optional `landings`/`approaches` counts; a flight without them counts as **one takeoff + one landing** (classified by its `takeoff`/`landing` fields). Lapse dates anchor to the event carrying the threshold-crossing unit. The 24-month recurrent-training gauge rides on the Documents system ("Recurrent Training" doc type). Everything is labeled *reference only*.
- `pdf.ts` / `pdfRender.ts` — **PDF export**. `buildPdfModel` (pure, eval-able) chunks the current pilot's flights into TC-style pages with page/forward/grand totals plus a summary (career totals, hours by type, currency, documents); `pdfRender.ts` draws it with jsPDF + autotable, both **dynamically imported** so they stay out of the page bundle.
- `aircraft.ts` — the built-in aircraft catalog (`AIRCRAFT_TYPES`) plus the **fleet** helpers: `fleetTypes(custom)` merges built-ins with the user's `AppData.fleet` (dedup by `normalizeAircraftCode`, built-ins win, sorted) for every picker; `aircraftName(code, custom?)` resolves names across both. Custom types are per-user (`AppData.fleet: AircraftType[]`), merge-synced by id like flights, and managed on the **Fleet page** (`(app)/fleet`) or added inline from the flight form's type dropdown. It's deliberately **per-user/local**, not a shared global catalog (a global write surface would break the app's strict per-user RLS model).
- `airports.ts` (Canadian ICAO DB + coord/label helpers; unknown codes resolve to **null**, never fabricated coords — the Route Map lists them for the pilot to place, saved per-user in `AppData.customAirports` which also shadows built-ins and feeds the From/To autocomplete), `logbook.ts` (pure `AppData` helpers), `dashboard.ts`.

### Native iOS (`ios/App`, `src/lib/native.ts` + bridges) — web bundle stays Capacitor-free
- The web bundle **must not import `@capacitor/core`.** `native.ts`'s `isNativeApp()` sniffs the injected `window.Capacitor` at runtime (returns false during prerender — branch after mount to avoid hydration mismatches); the bridges read `window.Capacitor.Plugins.*` directly. On the website these helpers report "unavailable" and the native UI hides itself.
- **Scan** (`ScanPlugin.swift` ↔ `scanBridge.ts`): VisionKit document camera → Vision text recognition, plus an optional **Foundation-Models** structured extraction on Apple Intelligence devices (iOS 26+). `scanAvailability()` returns why the model is/isn't usable (`AiReason`: `not-enabled`, `model-downloading`, `device-not-eligible`, `os-too-old`, `framework-missing`…), surfaced in the confirm sheet. `scanDocuments` (live camera) and `scanImages` (uploaded photos/PDFs) both feed `src/lib/scan.ts`.
- **Widgets** (`PilotLogbookWidget/*.swift` ↔ `WidgetPlugin`): `DataContext`'s `writeWidgetData` pushes a logbook summary to the home/lock-screen widgets on every state change.
- **Deep links**: the widget opens `pilotlogbook://new-flight`. `(app)/layout.tsx` listens for Capacitor `appUrlOpen`; because a cold launch emits the event before the listener mounts, the intent is also parked in `sessionStorage` and replayed, then dispatched as a `plb-new-flight` window event that the logger opens the flight form for.

### UI (`src/app`)
- **"Cockpit" theme, dark by default with a light mode**: slate-950 background with a cyan radial glow, cyan brand palette, `.card`/`.modal-card` surfaces and dark form controls in `globals.css`; palette in `tailwind.config.ts`. The **`TopBar` toggle** flips `data-theme="light"` on `<html>` and persists `plb_theme` in localStorage; a blocking inline script in the root `layout.tsx` applies the stored theme before first paint (no light/dark flash), so `globals.css` carries `[data-theme="light"]` overrides for the slate/text utilities.
- `(app)/` route group = the authenticated shell: left **`Sidebar`** (icon nav, collapses to icons under `lg`; its exported `NAV` list is the single source of page labels) + sticky **`TopBar`** (heading shows the **current page name** derived from `NAV`, sync badge, current user, theme toggle, Report Bug, Log Out). `layout.tsx` guards auth, installs error capture, handles widget **deep links** (see Native iOS), and **renders `Onboarding` in place of the shell until `data.profile.onboarded`**. One page per tab: `logger`, `dashboard`, `fleet`, `currency`, `routemap`, `duty`, `documents`, `pilots`, `bugs`. `/login`, `/privacy` and the onboarding wizard render outside the shell; `/` redirects to `/logger`.
- **Logger page**: the flight form is collapsed behind an **"Add a Flight"** button, with `ScanImport` (native OCR scan → confirm sheet) beside it; **`FlightTable.tsx`** is the densest component: inline "quick edit", checkbox range-select + bulk-edit, per-row delete, and a Columns panel that reorders/toggles `flightColumns`.
- **`ScanImport.tsx`** (used by the logger and Documents pages) drives the scan flow: camera / photo-PDF upload → `src/lib/scan.ts` → the confirm sheet that highlights low-confidence fields, flags duplicate flights, and lets the pilot add pages to a batch before saving. **Scans are never auto-saved.** Engines: iOS camera is always on-device; iOS *uploads* can opt in to cloud AI ("AI-enhance uploads" checkbox → `lib/cloudScan.ts` → `scan-extract` Edge Function, falling back to on-device results if the cloud call fails); on the **website** cloud AI is the only engine (button renders whenever Supabase is configured). The privacy page documents the opt-in; camera captures never leave the device.
- **Dashboard** (`dashboard/page.tsx` + `dashboard.ts`): ring-gauge cards for Flight Stats / Breakdown / Active Duty / CARs-Compliance, an aircraft-hours panel, document-status list, and a Customize panel backed by the per-user `dashboardHidden` metric list. CARs and active-duty math (`computeCars`, `computeActiveDuty`) live in `dashboard.ts` and read the caps for the pilot's CARs operation type from **`dutyLimits.ts`** (`effectiveLimits(profile)` → 703/704/705 flight-time/FDP/rest limits, with the 60-vs-70h 7-day option; `UserProfile.carsSubpart`/`duty7DayOption`, picked on the Duty page, default to the conservative 705 set). Reference only.
- **Onboarding** (`Onboarding.tsx`) is the two-step first-run wizard (profile → documents) that creates the primary pilot and writes `profile`. `DocumentForm.tsx` is shared by it and the Documents page.
- Route Map uses Leaflet via dynamic `import("leaflet")` inside `useEffect` (needs `window`), with `import "leaflet/dist/leaflet.css"`. User-supplied airport codes are HTML-escaped before going into Leaflet popups.

## Conventions
- `APP_VERSION` (`src/lib/types.ts`, currently `0.15.0`) is user-visible and attached to bug reports — bump it with meaningful releases. (`package.json` version is separate and not kept in lockstep.)
- Reference data and dedupe/CSV/migrate/documents logic must stay pure and framework-free in `src/lib`.
- `*.csv` and `.claude/` are gitignored — CSV files are personal flight data and must never be committed.
